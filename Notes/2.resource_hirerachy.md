# Google Cloud — Resource Hierarchy

## At a glance
Level 4: Organization node (Top)  
├── Level 3: Folders  
│   ├── Level 2: Projects  
│   │   └── Level 1: Resources (VMs, Cloud Storage buckets, BigQuery tables, etc.)

---

## Level 4 — Organization node
- Keyword: Organization  
- Definition: Top-level node representing your company/enterprise.  
- Purpose: Centralized governance — billing linkage, org-wide IAM & policies, audit visibility.  
- Use when: You manage multiple teams, projects, or billing accounts.

---

## Level 3 — Folders
- Keyword: Folder  
- Definition: Optional grouping layer to organize projects (by team, department, or environment).  
- Purpose: Apply policies and IAM once for many projects; policies inherit downward.  
- Note: Requires an Organization node.

---

## Level 2 — Projects
- Keywords: Project, Project ID, Project Name, Project Number  
- Definition: Project = main container for resources, APIs, quotas, and billing.  
- Key points:
  - Billing and quotas are per project.
  - APIs and services enabled per project.
  - Each resource belongs to exactly one project.
- Identifiers:
  - Project ID — user-chosen, globally unique string (used in commands/URLs).
  - Project Name — human-friendly label (not guaranteed unique).
  - Project Number — numeric, unique, immutable.
- Quick command: gcloud projects list

---

## Level 1 — Resources
- Keyword: Resource  
- Definition: Concrete cloud objects you run — VMs, buckets, databases, datasets.  
- Rule: Resources live inside one project and inherit policies from above.

---

## Policy & permission rules (short)
- DENY is evaluated first — explicit denies block access regardless of allows.  
- Grants at Organization → apply to all descendants.  
- Grants at Folder → apply to projects in that folder.  
- Grants at Project → apply only to that project and its resources.  
- Best practice: Grant least privilege at the narrowest scope.

---

## Resource Manager (what it does)
- Manage projects and folders: list, create, update, delete, recover.  
- Interfaces: Console, gcloud CLI, REST / RPC APIs.  
- Examples:
  - Create: gcloud projects create my-project-id --name="My Project"
  - Describe: gcloud projects describe PROJECT_ID

---

## Quick reference
- Hierarchy: Organization → Folders → Projects → Resources  
- Every resource belongs to exactly one project.  
- Use folders to group projects; use projects to isolate billing/apis.  
- Keywords: Organization, Folder, Project, Resource, IAM, Resource Manager, Project ID, Project Number
